# BQ40Z50 Multi-Channel SLFS Updater - User Manual

이 문서는 RP2040을 활용하여 다수(최대 6개)의 BQ40Z50 칩셋에 동시에 `.slfs` 펌웨어를 병렬로 업데이트하는 도구의 사용 설명서입니다. PC GUI를 구축하기 전, 시스템의 전반적인 하드웨어 구성과 파이썬 CLI 스크립트 사용법을 정리합니다.

---

## 1. 하드웨어 구성 (Hardware Setup)

다채널 동시 통신과 플래시 쓰기 작업은 많은 전력을 소모하므로, 하드웨어 구성 시 다음 사항을 반드시 준수해야 합니다.

*   **RP2040 모듈**: RP2040-Zero (또는 Raspberry Pi Pico 등)
*   **외부 전원 공급 (필수)**: USB 단일 전원만으로는 전류 부족 및 발열(Brown-out)로 인해 RP2040이 재부팅될 수 있습니다. 반드시 안정적인 외부 5V 전원을 인가해야 합니다.
*   **공통 접지 (Common Ground) ⚠️중요⚠️**: 외부 전원의 GND, RP2040의 GND, 그리고 통신 대상인 **모든 BQ 칩 기판의 GND는 물리적으로 반드시 하나로 연결**되어야 합니다. GND가 묶이지 않으면 I2C 통신 기준 전압이 흔들려 즉시 통신 에러(NACK)가 발생합니다.
*   **I2C 라인**: CH1 ~ CH6에 맞게 SDA/SCL 핀이 정확히 배선되어야 합니다.

---

## 2. 펌웨어 및 데이터 굽기 (Preparation)

새 RP2040 모듈을 처음 세팅할 때는 **[1] 실행 프로그램(UF2)**과 **[2] 업데이트할 데이터(SLFS)**를 순서대로 넣어주어야 합니다.

### 단계 1: RP2040 펌웨어(UF2) 업로드
1. RP2040의 `BOOTSEL` 버튼을 누른 채로 PC와 USB를 연결합니다.
2. 윈도우에 이동식 디스크(예: `RPI-RP2`)가 뜹니다.
3. 펌웨어 빌드 결과물인 `firmware.uf2` 파일을 해당 이동식 디스크 최상위 폴더에 복사(또는 드래그 앤 드롭)합니다.
4. 복사가 완료되면 보드가 자동으로 재부팅되며, 윈도우 장치 관리자에 일반 시리얼 포트(COM)로 인식됩니다.

### 단계 2: SLFS 데이터 파일 업로드 (RP2040 내부 플래시에 저장)
UF2 펌웨어만 올라가 있는 상태에서는 대상 칩에 구워줄 원본 데이터(`.slfs`)가 내부에 없으므로 업데이트가 불가능합니다. 파이썬 업로드 스크립트를 통해 RP2040 내부 플래시 메타데이터 영역에 `.slfs` 파일을 전송하여 저장해야 합니다.
```bash
# COM포트 번호(예: com6)와 굽고자 하는 .slfs 파일 경로를 지정합니다.
uv run --with pyserial python firmware/slfs_uploader.py -port com6 -file Reference_Data/BQU_pl4sm07_temp.slfs
```
*성공 시 `Data Upload Complete` 및 `Verification OK!` 메시지가 뜹니다. 이 작업은 새 보드 세팅 시, 또는 굽고자 하는 SLFS 파일이 변경되었을 때만 수행하면 됩니다.*

---

## 3. 다채널 업데이트 실행 (Running the Updater)

RP2040 세팅이 끝났다면, 메인 파이썬 스크립트(`bq_multi_updater.py`)를 통해 PC에서 업데이트 시작 명령을 내리고 실시간 진행률을 모니터링할 수 있습니다.

### 기본 사용법
연결된 COM 포트와 업데이트를 진행할 채널(`-ch`) 번호를 지정합니다.
```bash
# CH1, CH2 채널에 동시에 업데이트를 지시하는 경우
uv run --with pyserial python firmware/bq_multi_updater.py -port com6 -ch 1 2
```

### 연속 테스트 모드 (스트레스 테스트용)
`-loop` 파라미터를 추가하면 지정한 횟수만큼 쉬지 않고 반복하여 업데이트를 수행합니다.
```bash
# CH1~CH6 6개 채널 전부를 대상으로 연속 50회 업데이트 스트레스 테스트
uv run --with pyserial python firmware/bq_multi_updater.py -port com6 -ch 1 2 3 4 5 6 -loop 50
```

## 4. 트러블슈팅 (Troubleshooting)

### Q1. 시작하자마자 0.1%에서 `[ERROR] Code: -1` 또는 `-11` 에러가 나면서 죽습니다.
*   **원인 1**: 하드웨어 I2C 통신 NACK. 공통 접지(GND)가 묶여 있지 않거나, SDA/SCL 핀 접촉이 불량일 확률이 99%입니다. 선 연결을 1차로 점검하세요.
*   **원인 2**: 이전 작업 강제 종료 등으로 인해 BQ 칩이 **ROM Mode**에 갇혀 있는 경우입니다. 롬 모드에서는 기본 통신 주소와 명령어 규격이 다르므로 일반 업데이트 명령에 응답하지 않습니다. TI 전용 툴을 이용해 칩을 초기화(리셋)한 후 다시 시도하세요.

### Q2. 파이썬 실행 시 `FileNotFoundError` (COM 포트를 찾을 수 없음)가 뜹니다.
*   USB를 다시 꽂으면서 COM 포트 번호가 변경되었거나, 보드가 여전히 BOOTSEL 모드(이동식 디스크) 상태일 수 있습니다. 장치 관리자를 열어 현재 부여된 COM 포트 번호(예: `com3`, `com6`)를 정확히 확인하고 스크립트 인자에 반영하세요.

### Q3. 파이썬 실행 시 `OSError(22) ... I/O 작업이 취소되었습니다` 에러가 납니다.
*   이전 연속 테스트나 통신이 윈도우 단에서 비정상적으로 엉켜 COM 포트가 닫히지 않은 꼬임 상태(Deadlock)입니다. RP2040 보드의 USB 케이블을 완전히 뽑았다가 다시 꽂아주면(포트 리셋) 해결됩니다.

### Q4. 업데이트 도중 `SerialTimeoutException (Write timeout)` 이 뜨면서 멈춥니다.
*   보드 발열이나 일시적인 전력 부족으로 인해 RP2040 칩이 재부팅되면서 USB 연결이 끊어진 상황입니다.
*   반드시 외부 5V 전원이 제대로 꽂혀 있는지, 그리고 Core 0 절전 패치(`getchar_timeout_us(1000)`)가 적용된 최신 펌웨어가 올라가 있는지 확인하세요.
