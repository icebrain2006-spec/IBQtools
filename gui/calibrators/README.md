# IBQTools Calibration Architecture

This directory contains the core logic for running automated calibration sequences on Texas Instruments (TI) Battery Management System (BMS) ICs like the BQ40Z50.

## Folder Structure
- `calib_runner.py`: The Python execution engine that reads `.calib` text scripts line by line, converts them into SMBus commands, and communicates with the target IC (via the RP2040 firmware).
- `scripts/`: This folder contains the actual `.calib` scripts that define the step-by-step SMBus communication flow required to calibrate a specific IC.

---

## 1. Execution Flow (How it works)
When the user clicks "Start Calibration" in the GUI:
1. The GUI gathers the target calibration values (e.g., 3200mV for Cell 1, 12780mV for Pack) entered by the user.
2. It launches a background thread using the `CalibRunner` class (from `calib_runner.py`).
3. `CalibRunner` opens the `.calib` script (e.g., `scripts/bq40z50_voltage.calib`) and reads it line by line.
4. Each line is a simple text command (like `W`, `B`, `A`, `S`). The Python runner translates these into physical I2C/SMBus transactions via the Serial port to the RP2040 firmware.
5. Some commands (like `A` for ADC sampling or `S` for Saving DataFlash) contain complex IC-specific calculation logic embedded inside `calib_runner.py`.

---

## 2. `.calib` Script Syntax
A `.calib` file is a plain text file that acts as a macro for SMBus communication. It closely mirrors the logs generated by TI's EV2300/EV2400 tools.

### Standard Commands
- `; comment`: Lines starting with `;` are ignored (comments).
- `W 0x[Reg] 0x[Word]`: Write a 16-bit word to a register.
  - *Example:* `W 0x00 0x002D` (Send 0x002D to MAC Register 0x00 to Enable Calibration)
- `B 0x[Reg] 0x[Byte1] 0x[Byte2] ...`: Write a block of bytes to a register.
  - *Example:* `B 0x44 0x81 0xF0` (Send 0xF081 to MAC Data Register 0x44)
- `R 0x[Reg]`: Read a block of data from a register.
- `X [milliseconds]`: Delay execution for N milliseconds.

### Advanced/Custom Commands (Handled by `calib_runner.py`)
These commands trigger complex Python logic inside the runner rather than just sending raw bytes.
- `CHK_CAL [0|1]`: Polls the `ManufacturingStatus` register (0x0057) up to 10 times, waiting for the `CAL_EN` bit (bit 15) to become `1` (enabled) or `0` (disabled).
- `A 0x[Reg] [DelayMs] [Count]`: Advanced ADC Sampling. 
  - *Example:* `A 0x44 200 10` (Read register 0x44 every 200ms, collect 10 valid ADC samples, average them, and calculate the new Voltage Gains).
- `S 0x[Reg]`: Save DataFlash. 
  - *Example:* `S 0x4000` (Reads the existing 32-byte DataFlash block at 0x4000, modifies ONLY the voltage gain offsets using the gains calculated by the `A` command, and writes the block back).

## 3. How to add support for a New BQ IC
Different TI chips have entirely different memory maps and calibration procedures. To support a new chip (e.g., BQ20Z90, BQ34Z100):

### Step 1: Create the `.calib` Script
Use TI's bqStudio or EV2300 software to perform a calibration manually and sniff the I2C traffic. Convert that traffic sequence into a new text script (e.g., `scripts/bq20z90_voltage.calib`).
*Note: Make sure to follow the exact sequence of entering CAL mode, toggling raw ADC, sampling, and exiting CAL mode.*

### Step 2: Implement IC-Specific Logic in `calib_runner.py`
The `calib_runner.py` file must be updated to handle the new IC's data layout. 
Look for the `elif cmd == 'A':` and `elif cmd == 'S':` blocks in the `run()` method.

**For ADC Sampling (`A` command):**
- Different ICs return RAW ADC data in different formats or byte offsets.
- For example, BQ40Z50's `0xF081` response starts with a MAC echo, then 4 bytes of Coulomb Counter data, before finally presenting Cell 1 ADC at offset 6. Older ICs might present Cell 1 ADC at offset 0.
- Update the byte offsets (`struct.unpack_from`) inside the `A` command logic to match the new IC's datasheet.

**For DataFlash Saving (`S` command):**
- Different ICs store calibration DataFlash at different addresses and offsets.
- For example, BQ40Z50 stores Voltage Calibration at Subclass 104 (`0x4000`), with Cell Gain at offset 0, Pack Gain at offset 2, and Bat Gain at offset 4.
- Update the Read-Modify-Write logic in the `S` command to pack the new gains into the correct byte offsets for the target IC.

### Step 3: Link it in the GUI
Finally, modify `gui/tabs/calibration_tab.py` to point to your new script when the user selects the corresponding IC in the UI.
